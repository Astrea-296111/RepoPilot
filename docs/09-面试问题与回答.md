# 09｜30 道面试问题：先说 30 秒，再按源码展开

用法：先遮住「深入版」自己说 30 秒，再打开源码找证据。基础问题保留原有学习顺序，最新架构与 10 个集中追问见 [项目讲述](16-项目STAR与简历.md)；FakeLLM Demo、真实模型评测和 Docker runtime 必须分清。

### Q1：你的项目是做什么的？

**30 秒口语版：** RepoPilot 是小型 Coding Agent，读仓库、检索、规划、改文件、跑测试，失败再调整，最后给 Diff。

**深入版：** CLI/API 共用 `RepoPilot.run`；Demo 先失败再通过，但用的是固定脚本 FakeLLM，不证明真实模型修复率。**源码：** `repopilot/agent/agent.py`、`repopilot/cli.py`。

### Q2：Agent 和普通调用 LLM 有什么区别？

**30 秒口语版：** 普通调用得到文字；Agent 把模型动作交给工具执行，让真实结果参与下一轮决策。

**深入版：** `ToolResult` 中的输出和 exit code 是 Observation，逐步进入 State；模型自己不执行 shell。**源码：** `agent/agent.py:run`、`tools/base.py:ToolResult`。

### Q3：为什么不用 LangChain？

**30 秒口语版：** 这个学习项目需要我能看见循环、校验和边界，所以只用小接口连接模型。

**深入版：** 当前只有 Planner、一个 Agent Loop 和六个工具；自写便于理解每个 Observation 何时进入上下文，未来规模增大再比较框架。**源码：** `agent/agent.py`、`llm/base.py`。

### Q4：Agent Loop 怎么设计？

**30 秒口语版：** `while` 限步循环，每轮构造上下文、问模型、校验动作、执行工具并记录观察。

**深入版：** final 后程序复跑计划测试；失败留在循环，成功取 Diff；每轮持久化状态。**源码：** `agent/agent.py:RepoPilot.run`。

### Q5：为什么需要 Repo Map？

**30 秒口语版：** 地图先告诉模型仓库里有什么函数，再按需打开文件，减少无关源码。

**深入版：** Python AST 抽取类、函数、签名和 import；文件大小和数量有上限。**源码：** `context/repo_map.py:build_repo_map`。

### Q6：10 万文件怎么办？

**30 秒口语版：** 当前 V1 扫描上限 4000，不能直接宣称支持 10 万；我会先按目录分层、增量索引再检索。

**深入版：** 缓存每文件 AST 与内容摘要，只更新变化文件；检索先按目录/语言过滤，然后 BM25/向量召回并重排。**源码：** `context/repo_map.py:iter_source_files`。

### Q7：为什么不用全部 embedding？

**30 秒口语版：** 小项目先用低成本、能解释的文件名、符号和词频；embedding 要多一套索引与更新逻辑。

**深入版：** 语义召回对同义描述有帮助，但可能漏掉精确 API 名；当前中文只用有限词表，后续做混合检索。**源码：** `context/retrieval.py:retrieve`。

### Q8：Context 爆了怎么办？

**30 秒口语版：** 设字符预算，优先留下任务、计划和最近观察，压缩旧历史，再截断地图。

**深入版：** 目前是字符近似，不是准确 token；过大的必要内容也可能被截掉，未来可加入 tokenizer 和分层摘要。**源码：** `context/manager.py:ContextManager.build`。

### Q9：Tool 输出特别长怎么办？

**30 秒口语版：** 限制输出长度，保留开头、结尾和错误相关行。

**深入版：** 当前匹配 `error/failed/traceback/exception`，适合常见测试输出；复杂日志仍可能漏关键内容。**源码：** `tools/shell.py:bounded_output`。

### Q10：模型一直重复执行同一个命令怎么办？

**30 秒口语版：** 同一工具和参数连续第二次反馈与复用成功只读观察，第三次要求转向，第四次停止，总步数仍有限制。

**深入版：** JSON 排序后取指纹，只抓完全相同动作；交替命令仍需未来做进展检测。**源码：** `agent/agent.py:run` 的 `fingerprint`。

### Q11：为什么用 Docker？

**30 秒口语版：** 命令是危险工具，默认让它在临时、禁网、限资源容器中运行，降低主程序受到的影响。

**深入版：** 镜像预装 pytest，仓库可写挂载；进程数、内存、CPU 和超时均受限。**源码：** `sandbox/docker.py:DockerExecutor.run`、`Dockerfile.sandbox`。

### Q12：Docker 真安全吗？

**30 秒口语版：** 不绝对安全，目标仓库可写、daemon 和内核仍是受信任部分。

**深入版：** 容器使用宿主 UID/GID；root 用户、镜像来源、宿主漏洞和挂载删除都要考虑，所以先用副本和 Git。**源码：** `sandbox/docker.py`、`README.md` 安全说明。

### Q13：LLM 生成危险命令怎么办？

**30 秒口语版：** `run_command` 属于 risky，默认交互审批；可选 Docker 限制其执行环境。

**深入版：** `auto` 会跳过审批，只适合可信副本。当前没有完整命令语义分析或允许列表，不能声称能识别所有危险命令。**源码：** `agent/agent.py:_permitted`、`tools/shell.py`。

### Q14：Agent 修改错代码怎么办？

**30 秒口语版：** 单次补丁要求旧文本恰好命中一次，最后跑测试并展示 Git Diff 给人审查。

**深入版：** 测试和精确替换不能保证语义正确；先在 Git 副本运行，必要时人工回滚。**源码：** `tools/filesystem.py:ApplyPatch`、`tools/git.py:GitDiff`。

### Q15：怎么判断任务完成？

**30 秒口语版：** 模型提出 final 后，程序重新执行计划测试；通过才把状态标为 completed。

**深入版：** 只验证计划的测试命令是否成功，不等于所有功能正确；测试覆盖率和人工验收仍重要。**源码：** `agent/agent.py:run` final 分支。

### Q16：测试一直失败怎么办？

**30 秒口语版：** 把退出码和关键错误反馈回模型，允许继续修，但最多 `max_steps`。

**深入版：** 重复观察实际进入下一轮 prompt；第四次相同决定停止；会话保留错误与改动，便于人工接手。**源码：** `agent/agent.py:run`、`agent/state.py:AgentState`。

### Q17：怎么评估 Coding Agent？

**30 秒口语版：** 每个任务先确认基线失败，再在干净副本运行，最后检查测试结果、预期文件、步骤与工具数。

**深入版：** 脚本化开发集有 25 题，另有固定 10 个历史 Bug ×3 重复 ×2 方法的真实模型对照；patch resolved 与 completed+resolved 分开，保留失败、token 和端到端耗时。**源码：** `eval/run_eval.py`、`eval/tasks.json`。

### Q18：为什么需要 Planner？

**30 秒口语版：** 动手前给一个能讲清楚的方向：目标、疑似文件、步骤、测试命令。

**深入版：** 它只调用一次模型、Pydantic 验证，不是复杂多 Agent 调度；后续观察可以推翻初始猜测。**源码：** `agent/planner.py:plan_task`。

### Q19：Planner 错了怎么办？

**30 秒口语版：** 把计划当假设，让 `read_file`、`search_code` 和测试输出纠正它。

**深入版：** 当前最终复验仍沿用初始 `test_command`，如果计划选错测试可能误判完成，需要后续增加测试发现/人工指定机制。**源码：** `agent/planner.py`、`agent/agent.py:run`。

### Q20：如果模型 JSON 输出不合法怎么办？

**30 秒口语版：** Pydantic 校验失败要求重写一次，连续失败明确报错并保存会话。

**深入版：** Planner 和 Agent 各自最多两次尝试；工具参数另在工具内校验。**源码：** `agent/planner.py:plan_task`、`agent/agent.py:_action`。

### Q21：如何支持 Java 项目？

**30 秒口语版：** 当前 Java 只有浅层正则符号，真正支持要加 Java 解析器、构建工具和沙箱镜像。

**深入版：** Maven/Gradle 测试命令、依赖缓存、模块关系和 AST 抽取都需适配，不只是新增扩展名。**源码：** `context/repo_map.py`、`sandbox/docker.py`。

### Q22：如何支持百万行代码库？

**30 秒口语版：** 用增量索引和分层检索，不能每轮扫描全仓或把地图全放模型里。

**深入版：** 按文件哈希更新符号、按模块过滤、Top-K 片段按需读取，检索质量和延迟单独评测。当前 4000 文件上限很明显。**源码：** `context/repo_map.py`、`context/manager.py`。

### Q23：如何增加 Embedding Retrieval？

**30 秒口语版：** 按函数/文件片段生成向量，保存文件路径和版本，需求向量检索后再读原文。

**深入版：** 处理更新、删除、重排和不同模型的向量兼容；不要仅把全文件丢给向量库。当前还没有这套实现。**源码起点：** `context/retrieval.py`。

### Q24：如何做 BM25 + Vector Hybrid Retrieval？

**30 秒口语版：** BM25 擅长精确词，向量擅长语义；先各取候选，再归一或用排名融合，最后按符号/路径重排。

**深入版：** 用带标准答案的任务集调参数与 Recall@K，防止融合权重凭感觉；V1 仅有简单规则评分。**源码起点：** `context/retrieval.py`。

### Q25：如果多个 Agent 同时改文件怎么办？

**30 秒口语版：** V1 没有多 Agent 并发编辑；未来用隔离 Git worktree、锁和提交冲突检查。

**深入版：** `ApplyPatch` 的旧文本单一匹配能发现部分冲突，但没有事务或版本号，不能替代并发控制。**源码：** `tools/filesystem.py:ApplyPatch`。

### Q26：为什么当前版本没有做 Multi-Agent？

**30 秒口语版：** 单 Agent 已能解释完整读、改、测闭环；并行会增加状态、冲突和成本，V1 先验证基本可靠性。

**深入版：** 当任务可清晰拆分且单 Agent 基线稳定时，再测并行带来的收益是否超过协调代价。**源码：** `agent/agent.py:RepoPilot`。

### Q27：为什么同时保留 Custom 和 LangGraph？

**30 秒口语版：** Custom 便于讲清状态与策略；LangGraph 用六个真实节点和条件边表达同一流程，两者共享工具、安全边界和独立验证。

**深入版：** LangGraph 使用 InMemorySaver 测试进程内 node resume；跨进程仍由 JSON SessionStore 桥接，不宣称数据库持久化或 exactly-once。**源码：** `agent/agent.py:run`。

### Q28：如何减少 Token 成本？

**30 秒口语版：** 地图代替全仓源码，检索 Top-K，截断测试输出，旧历史摘要化，设上下文预算。

**深入版：** 当前 FakeLLM 用量为 0，不能说节省了百分之几；真实 provider 返回 usage 后才能和基线比较。**源码：** `context/manager.py`、`agent/state.py:token_usage`。

### Q29：项目最难的地方是什么？

**30 秒口语版：** 最难是让模型输出的动作、真实环境结果和安全边界保持一致，而不是只接通 API。

**深入版：** 我用协议校验、工具结果、测试复验、持久化和限步分别处理格式、执行、结果、恢复和循环问题；真实模型结果见历史与本轮报告，样本规模和兼容性限制仍然存在。**源码：** `agent/agent.py`、`tools/base.py`。

### Q30：如果再给你两周会优化什么？

**30 秒口语版：** 扩展独立 Bug 和完整仓库测试，按兼容性失效轨迹做对照，再强化容器与 API 边界。

**深入版：** 逐任务记录基线、成功、调用数、耗时、费用；做 BM25+符号召回消融；加入 API 认证和命令策略。先拿证据再写简历指标。**源码起点：** `eval/run_eval.py`、`context/retrieval.py`、`api/server.py`。
