# 08｜从空环境到跑起来

先选最简单的路线：装 Python 3.11+ 与 Git，在项目目录建立虚拟环境。没有模型 Key，就只跑 FakeLLM Demo；真实模型需要提供 OpenAI-compatible 的 Base URL、Key、Model。Docker 要跑真实 Agent 的默认执行器，需要另建沙箱镜像。

## macOS / Linux

```bash
cd RepoPilot
python3 --version
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
cp .env.example .env
python -m pytest -q
python -m repopilot.cli --help
```

## Windows PowerShell

```powershell
cd RepoPilot
py -3 --version
py -3 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
Copy-Item .env.example .env
python -m pytest -q
python -m repopilot.cli --help
```

PowerShell 拒绝激活脚本时，在该终端执行 `Set-ExecutionPolicy -Scope Process RemoteSigned`，或者直接使用 `.venv\Scripts\python.exe -m ...`。装依赖时保持 `.[dev]` 的引号，安装成功后 `python -m pytest` 比依赖系统 PATH 的 `pytest` 命令更稳。

## Demo 与真实模型

先运行 `python eval/run_eval.py`：它会新建临时副本，不改原始例子。CLI 交互 Demo 请按 README 复制、`git init/add/commit` 后执行 `python -m repopilot.cli run PATH "修复重复邮箱注册失败的问题" --fake-demo --executor local --approval auto`。真实模型填写 `.env` 并去掉 `--fake-demo`；给任意仓库运行前创建 Git commit，并优先用默认 `--approval ask`。

```env
LLM_BASE_URL=https://your-provider.example/v1
LLM_API_KEY=your-secret
LLM_MODEL=your-model-name
```

不要提交 `.env`。会话记录虽然不存配置的 Key，但模型/工具输出可能含敏感数据；只在可信仓库使用，传递日志前自己检查。

## Docker CLI 沙箱和 API 服务

```bash
cp -R examples/demo_repo workspaces/demo_repo
git -C workspaces/demo_repo init
git -C workspaces/demo_repo add .
git -C workspaces/demo_repo -c user.email=demo@example.invalid -c user.name=Demo commit -m baseline
docker build -f Dockerfile.sandbox -t repopilot-sandbox:dev .
python -m repopilot.cli run ./workspaces/demo_repo "修复重复邮箱" --executor docker --approval ask
# Linux: 在 .env 中把 REPOPILOT_HOST_UID/GID 改为 id -u / id -g
docker compose build
docker compose up -d
curl http://127.0.0.1:8000/health
```

第一条创建**命令沙箱镜像**，Compose 创建**API 服务镜像**；两者不同。API 没有认证，Compose 只绑定本机并挂 `workspaces/`，不挂项目 `.env` 文件。请求 API 的完整例子在 README；容器里的仓库路径是 `/workspace/repos/demo_repo`。API 任务查找在服务进程内，进程重启后可用 CLI 查询原仓库的 session 文件。Compose 默认不挂 Docker socket，任务须显式选择容器内 `executor=local`；不要向公网开放服务。

## 常见错误速查

| 现象 | 常见原因 | 解决办法 |
| --- | --- | --- |
| `python` / `py` 找不到 | Python 未安装或 PATH 未更新 | 安装 3.11+；Windows 用 `py -3`，macOS/Linux 用 `python3` |
| `pip` 找不到 | 虚拟环境未激活或 PATH 错 | 使用 `python -m pip install -e '.[dev]'` |
| `pytest: not found` | 没装 dev 依赖，或脚本目录不在 PATH | 激活 venv；用 `python -m pytest -q` |
| `Docker executable not found` / daemon 未启动 | 未装 Docker 或后台服务未启动 | 安装并启动 Docker，运行 `docker info`；可信副本可临时选 local |
| `Unable to find image repopilot-sandbox:dev` | 未构建沙箱镜像 | `docker build -f Dockerfile.sandbox -t repopilot-sandbox:dev .` |
| `LLM_API_KEY` / `LLM_MODEL` 缺失 | `.env` 未复制/未填，或启动目录不对 | 在项目目录复制并填写 `.env`；无密钥先用 `--fake-demo` |
| HTTP 401 | Key 不正确、权限不足 | 在 provider 控制台确认 Key，检查 Base URL；不要把 Key 贴到日志 |
| 模型名错误 / HTTP 404 | `LLM_MODEL` 不在该服务下 | 查看提供方实际模型 ID，确认 URL 包含 `/v1` |
| Docker bind mount 失败 | 路径共享权限、Docker Desktop 未共享盘符 | 使用绝对路径，检查 Docker 文件共享和宿主文件权限 |
| 测试时 `Permission denied` | 容器 UID/GID 与仓库所有者不匹配 | 在 `.env` 中设 `REPOPILOT_HOST_UID/GID` 为宿主 `id -u` / `id -g`，检查目标目录写权限 |
| 测试包缺失 | 沙箱镜像只预装 pytest，且禁网 | 扩展 `Dockerfile.sandbox` 预装项目依赖，再改镜像名或重建 |
| `git diff failed` | 目标不在 Git 工作树或没有权限 | 在仓库初始化 Git，并做基线提交 |
