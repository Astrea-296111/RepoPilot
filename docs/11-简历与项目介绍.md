# 11｜简历与项目介绍：按验证程度选择说法

## A. 30 秒项目介绍

「我做了一个 Python Coding Agent：输入仓库和修复需求，它用 AST 做 Repo Map，按文件名、符号和关键词找可能的文件，先生成计划，再让模型按 JSON 协议逐步读文件、改代码和跑测试。程序对路径、审批、超时和步数设边界，测试失败会反馈给下一轮；最后程序复验并输出 Git Diff。现在我用 1 个脚本化 Demo 和自动化测试验证了完整工作流，真实模型跨任务表现仍待测。」

## B. 2 分钟项目介绍

「我希望理解 Coding Agent 为什么不是一次模型调用。最先遇到的问题是大型仓库不能全部塞入上下文，所以我用 Python AST 抽取类、函数、签名和 import，生成小地图，再用简单、可解释的文件名/符号/词频评分选 Top-K。Planner 根据任务与地图给出目标和测试命令。Agent 是一个有 `max_steps` 的 while 循环：每轮构造有限上下文，模型返回 JSON 工具调用或 final；Pydantic 验证后，程序经审批执行文件或命令工具，并记录观察。工具输出截断，近期历史保留，旧历史压缩；重复三次完全相同动作停止。模型说 final 也不能直接相信，我让程序重新跑计划的测试，失败继续循环，成功才取 Git Diff。工具命令默认进限资源、禁网的 Docker 容器，可显式选 local；会话逐步保存为 JSON，另有 CLI 和简单 REST API。测试验证包括越界路径、超时、JSON 修复、循环检测和一个先失败再成功的重复邮箱 Demo。Demo 用 FakeLLM 固定脚本，只证明 harness 的执行流；真实模型能力、成本和大型基准我尚未测量。」

## C. 简历项目描述（完成并通过当前测试后）

- 独立实现 Python Coding Agent 的 Planner、显式 Agent Loop 与 JSON/Pydantic 工具协议，支持测试失败反馈、`max_steps`、重复调用停止和最终程序侧复验。
- 使用 Python AST 构建 Repo Map，结合文件名、符号与文本词频检索相关文件，并通过输出截断、历史摘要和字符预算控制长任务上下文。
- 实现仓库路径防越界、审批、限时 Local/Docker 执行、JSON 会话、CLI 与 FastAPI；用自动测试和 1 个先失败后修复的 FakeLLM Demo 验证工作流。
