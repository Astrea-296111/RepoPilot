# 10｜七天源码阅读路线

每天先自己回答问题，再对照代码；不要把函数名背成简历话术。故事线始终是「修重复邮箱」。如果每天只有一小时，前 15 分钟手跑命令，后 45 分钟读源码与做笔记。

| 日程 | 目标与必看函数 | 当天能回答的问题 |
| --- | --- | --- |
| Day 1 | `cli.py:run` → `agent/state.py:AgentState` → `agent/agent.py:RepoPilot.run`；画出 while 循环 | 模型、工具、观察、状态各在哪里？什么时候结束？ |
| Day 2 | `tools/base.py:Workspace.resolve`、`tools/filesystem.py:ReadFile/ApplyPatch`、`tools/shell.py:LocalExecutor.run` | 为什么路径不能越界？补丁为何只替换一次？超时如何处理？ |
| Day 3 | `context/repo_map.py:build_repo_map`、`context/retrieval.py:retrieve` | AST 取了哪些信息？文件为什么排名靠前？会漏掉什么？ |
| Day 4 | `context/manager.py:ContextManager.build`、`tools/shell.py:bounded_output` | 长输出如何压缩？预算用的是什么单位？ |
| Day 5 | `sandbox/docker.py:DockerExecutor.run`、`Dockerfile.sandbox` | 命令在何处执行？容器能写哪里？还有哪些风险？ |
| Day 6 | `api/server.py:start/get_task`、`session/store.py:save/load`、`llm/openai_compatible.py:chat` | REST 请求如何变为会话？重启后什么仍在？Token 数据从哪里来？ |
| Day 7 | `examples/demo_repo`、`eval/run_eval.py:main`、`tests/test_core.py:test_agent_loop_demo_end_to_end` | 从失败基线到最终 diff 的证据是什么？哪些能力仍未验证？ |

Day 1 的具体练习：在纸上写 `while` 三行伪代码；Day 2 人工构造 `../../x` 试 `Workspace.resolve`；Day 3 修改任务词看检索顺序；Day 4 让测试输出超过预算；Day 5 不必运行危险命令，只读 Docker 参数并解释；Day 6 打开一个 session JSON；Day 7 跑 `python eval/run_eval.py`，对照上章的 6 步 7 工具调用。不要在原始 Demo 上随意修补，评测需要失败基线。

### 这一章你面试时应该能说什么

「我能从 CLI 请求一路追到 Agent 循环、上下文、工具和会话；我亲手复现了失败基线、修复后通过和 Git Diff，并知道 FakeLLM 与真实模型评测的边界。」

2. 如果检索漏了目标文件怎么办？
3. Docker 与审批分别挡住什么问题？
4. 哪一个测试最能证明完整闭环？
